# 设计说明

## 结构与数据流

`ResearchMode.ps1` 提供菜单和非交互入口；`src/ResearchMode.psm1` 实现扫描、方案、执行、日志和恢复；`rules/apps.json` 只描述用途与初始建议；skill 调用同一入口。

扫描使用 Windows CIM 和 Get-Process，把相同可执行文件路径的进程归到一项。没有路径时用未解析的名称分组，避免把可读和不可读的同名进程误当成同一身份。路径不可读时不执行普通应用动作。

批准指纹由标准化路径、可执行文件 SHA-256、关联服务名称和服务启动命令构成。元数据中的发布者仅作说明，不作为可信签名断言。软件更新使指纹失效；不用旧批准静默接受新二进制。

每次方案绑定具体 PID 和启动时间，进程启动时间统一到 CIM 与 Process 接口共同的微秒精度。JSON 时间戳保持 UTC 字符串以兼容 PowerShell 5.1 和 7.5+ 的反序列化差异。执行前先预检整个方案，每个动作前再核验一次。新出现的普通应用实例不在旧方案的关闭范围；服务进程集合发生变化时重新审查。

## 执行和权限

方案只是内置动作的数据，不执行其中的脚本或命令行。调用方必须提交审查时的文件 SHA-256 `PlanHash`；该值用于检测审查后文件变化，不是数字签名或权限隔离。程序不常驻、不自动提权。以管理员权限启动意味着本机用户信任了整个程序和数据目录，因此不支持把陌生人的方案导入后提权执行。

服务只能通过服务控制器正常停止。运行中的依赖服务会阻止操作，不使用 `-Force` 扩大范围；共享服务进程不支持。安全软件提供手动厂商入口，不自动降级成强杀。没有服务权限时如实记录失败。

服务依赖、路径和 PID 校验不能消除所有进程状态变化的竞争窗口；这是有人工审查的个人本机工具，不是抗恶意同用户并发修改的管理服务。不要在不可信软件正主动修改进程、服务或数据目录的环境下依赖它提供隔离保证。

## 日志与恢复

动作前写入 `pending`，请求执行前写入 `acting`，结束后写入实际状态。文件采用同目录临时文件后替换。崩溃可能留下 `pending` / `acting`，恢复流程不会猜测其最终状态。用户应结合系统状态手动核对。

恢复只处理 `stopped` 且可恢复的记录。文件不变时，以原可执行文件无参数启动一次，或重新启动原服务。不回放原进程命令行，避免把临时参数和潜在凭据变成可重复执行的任务。已运行的程序不重复启动。已成功恢复的记录会标记，重复调用不会再启动。

启动时使用隐藏窗口，避免自动弹出终端；部分交互程序可能需要从托盘或任务栏手动打开。不能恢复原应用内部状态。启动后很快退出的程序可能转交给其他实例，本版保留手动确认信息。

## 验证范围

自动测试使用临时编译的独立进程验证实际扫描、强制结束、预演、批准、实例范围和恢复。不对本机真实服务执行启停；服务依赖和受保护服务检查使用模拟数据验证。真实厂商软件的正常退出和服务兼容性需要按各软件版本补充受控人工验证，不应从一个成功测试外推为全部软件可用。
